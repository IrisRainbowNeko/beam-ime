## 本机自动验证

- C++ 核心：按键规范化、UTF-8、混输对齐、协议错误类型、服务不可用兜底。
- Python：模型文件校验与原子替换、配置保留、文件安装升级与回滚、prompt 契约。
- 真实模型 CPU 集成：错误请求后服务继续运行，生成候选，上下文切换。
- PowerShell 7 与 Windows PowerShell 5.1：重复安装、恢复原文件、中文/空格/方括号路径、保留用户修改、复制失败回滚、安装脚本语法。
- Windows 安装脚本：官方小狼毫的空版本文本、数值版本和架构检查、空配置初始化、失败安装卸载，以及宿主改变时保留恢复备份。
- Arch 构建：独立 C++ daemon、动态 CPU / Vulkan 后端及 librime 插件。
- Fedora 44 隔离环境：原生构建、RPM 安装、`lib64` 下的 CPU daemon、真实模型回归，以及安装后 Rime 插件的候选、上屏和停服务后的词典兜底。
- 隔离 Rime 用户目录：方案部署、候选、上屏，以及停止 daemon 后的雾凇输入。
- Windows Wine：中文与空格程序/模型路径，不提供 Vulkan DLL 的 CPU 启动与生成。
- Windows Unicode GUI 宿主：合并 Rime DLL 的日志初始化，覆盖 glog 的 `__argv` 修复。
- GitHub Actions：Ubuntu 24.04 完整编译、CTest 和 `.deb` 生成；Windows runner 的安装恢复测试。

## Windows 11 安装修复验证

在 Windows 11 Pro x86_64 虚拟机（系统版本 10.0.26100，4 vCPU / 4 GiB）中，
使用独立磁盘覆盖层和测试用户，开启 UAC 后完成：

- 复现已发布 Beta 2 的安装失败、卸载失败；官方小狼毫的文本版本为空，数值版本为 0.17.4.0。
- 修复脚本完成失败安装的卸载，未写入小狼毫时不请求系统恢复。
- 修复后的离线 EXE 在中文与空格目录安装、重复安装，兼容首次安装的空 `default.custom.yaml`。
- 保留中文与空格路径的自定义模型和 CPU 设置，安装后诊断确认模型已由 CPU 后端加载。
- 卸载后原 `rime.dll` 的 SHA-256 与安装前一致，保留模型、用户词库和安装后修改，移除 Beam 进程及卸载登记。

模型服务直接请求 `nhsj` 得到 `你换手机`；单次 CPU 生成约 1.7 秒。
该虚拟机上默认 400 ms 的 Rime 等待预算触发了词典兜底，已验证其候选和上屏。
这次验证覆盖安装链路，不作为真实 GPU 性能或所有桌面应用输入体验的结论。

真实模型用本次发布的 GGUF，使用隔离 socket，不替换桌面正在运行的输入法。
这些检查验证工程行为，不是大规模准确率评测。

## Python 原型个性化验证（2026-10-07）

Arch 本机与 Ubuntu 24.04、Fedora 44 隔离系统的核心、SQLite 学习和 Python CTest 均通过。
三个 Linux 环境均验证了 Rime 确认上屏采集一条、取消不采集，以及停服务后的词典候选和上屏。
专项测试覆盖混拼、多音字、重复事件、暂停/关闭、候选缓存、组词边界切换、双连接与断连、损坏 adapter 保留当前版本及成对回退。

Linux 与 Windows 的 11 项学习专项测试通过；用微型 Qwen3 在 microbatch 内中断后恢复，
最终 adapter 所有张量与连续训练逐项一致。Windows 测试使用默认区域编码，覆盖中文、空格、长路径及 CUDA 下载失败保留 CPU 组件。
训练进度采用追加式 JSON-lines，避免 Windows 读取进度时阻止文件替换；不完整的末行留待写完后消费。

Windows 11 本轮虚拟机为 8 vCPU / 8 GiB，通过 QEMU Guest Agent 以 SYSTEM 执行，使用隔离的中文用户数据目录。
完成真实发布 Q8 模型上的采集、CPU 训练、microbatch 暂停与续跑、GGUF 导出和自动激活。
两次覆盖安装保留记录及 adapter；中文目录下 YAML、Lua、OpenCC 和用户词库均正常，停服务后仍可上屏。

原版 Weasel 0.17.4 的部署程序在本机默认区域编码下，对全新中文空目录也退出 `0xc0000409`，ASCII 空目录部署成功。
首次卸载因此保留恢复入口；重试卸载成功清理程序登记。此项不记作一次性完整卸载通过。
暂停响应 2.36 秒，训练进程峰值 RSS 2564.7 MiB。

## QVAC 原生学习验证（2026-10-07）

发行训练入口已切换为 QVAC Vulkan，上一节 Python 原型测量保留作历史对照。
CPU 和 AMD 780M Vulkan 的 CE/KL 数值梯度、全局梯度裁剪及动态梯度累积重置通过。
微型 Qwen3 在 microbatch 内暂停后续训，与连续训练的 14 个适配器张量逐项一致；完整任务再次导出也通过。

发布 Q8 模型完成全线性 r8、个人 CE + 0.25 保底 CE + top32/剩余概率 KL 的 24 步训练、暂停续训和 GGUF 导出。
同机全链路为 218.6 秒（已有部分基座教师缓存，包含本轮同码生成和暂停续训），暂停退出 0.83 秒。
训练进程峰值 RSS 356.4 MiB，此数字不含 Vulkan 驱动管理的设备内存。
新的适配器在 daemon 的 CPU / Vulkan 后端通过加载、组词屏障、禁用、回退、损坏文件保留旧版本及基座变更测试。
通过 `learning install/train` 启动原生组件，沿用上一轮优化器训练、自动激活并回退也已完成。
Linux 发布组件在 Ubuntu 24.04 从锁定源码构建，通过 Arch / Ubuntu / Fedora 的加载与数值测试。
压缩资产为 Linux 26.14 MiB、Windows 33.72 MiB，不包含 Python、PyTorch 或第二份基座。

Windows 11 虚拟机通过原生组件离线安装、重复安装、中文/空格路径加载、CPU 数值梯度和微型模型续训测试；
测试驱动使用开发用 Python，实际训练由原生 EXE 完成。安装/卸载文件回归也通过。
该 VM 没有 Vulkan GPU，Windows Vulkan 训练仍需真实显卡验证。
